首段 PCM 是生成出数组的时间，不包含模型加载、网络和扬声器。峰值 RSS 取整个进程；请求形状与内存池会影响结果。只验收了短句，未证明长文本或多用户并发稳定。

省内存，与释放主要瓶颈，是两件事。

8 句初测中，BERT 从 FP32 换成 INT8，BERT 阶段中位耗时约 0.158 → 0.059 秒；声学生成器仍约 4 秒。先优化声码器输出，比宣称“量化后快几倍”更符合实际。

64 帧块更早出首段，但重复计算太多，总 RTF 约 1.05。128 帧是这轮短句里更均衡的折中；256 帧吞吐更好，但需要等更久才有首段。

WHAT WE PROVED / WHAT WE DIDN'T

把“确实保留了什么”讲清楚。

01 / 部署保真

FP32 没有另换一套声音

相同外部噪声下，实板与 x86 的 8 句输出长度全部一致，PCM RMSE 为 1.88e−6～4.89e−6。验证的是后端数值保真，不能推导“像本人多少分”。

02 / 分块边界

16 帧上下文不是随便挑的

4 / 8 帧仍有边界误差；16 帧在导出验证中达到约 1e−8 浮点 RMSE。实板 128 帧分块的三条匹配句，与整句 PCM 最大差异不超过 1 个 16-bit LSB。

03 / 量化边界

只动 BERT，也不是无损

INT8 特征余弦约 0.990～0.991，但部分句子时长与波形改变。这些数字不是听感评分；低内存版必须另外听，不能默认替代 FP32。

04 / 一个反例

最低 CER，未必值得用

删除 BERT 后，8 句 CER 从 32.20% 降到 25.99%，但破坏了训练条件，多数句子时长也变了。因此不把它当成优化方案，更不按 CER 决定音色。

还发现了内容完整性问题

该固定中文 frontend 会丢弃拉丁字母，影响“3D”“YQ”等输入。研究记录保留原文 CER 与有效文本 CER，绝不靠改目标文本隐藏漏字；公开运行器现在默认拒绝此类输入，需显式转写成中文。

WHY THE SAME MODEL CAN SOUND DIFFERENT

CosyVoice 的对比条件，补齐了。

之前用了情绪指令模式。这次补做保留参考语音 token 的零样本模式：同权重、同参考、同逐句种子，各 8 句。

模式基础 CER ↓热态 GPU RTF ↓已证明什么

官方 instruct2 路径会移除 LLM 的参考语音 token；zero_shot 保留 token 并加入准确转写。这是推理条件差异，不是“已经证明声音不够像的原因”。两种模式已放在上面的同题试听中。

GPT‑SoVITS 已做专门训练，而 Cosy 仍是通用模型参考克隆；Bert 公共音色的训练数据未知。数据、训练、参考风格与模式是混杂因素，不能把当前听感推广为架构排名。
